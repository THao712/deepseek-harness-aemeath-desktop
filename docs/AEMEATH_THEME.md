# 爱弥斯 DeepSeek Harness 主题规范

本主题以角色的身体与外貌识别特征为唯一视觉来源。武器、外在装备和场景道具不进入主题语法。整体方向是“深梅夜色中的星瞳与晶羽”：欢迎区和启动页允许出现绚丽的瞳环、星尘与晶羽折射，进入实际会话后仍保持清晰、低干扰的阅读层级。

## 1. 角色身体特征解构

### 眼眸与视线

- 虹膜主色为饱和金橙，靠近瞳芯转为明亮暖金，外围压入少量赤褐阴影。
- 瞳孔核心呈四向或八向星芒结构，不使用普通圆点作为唯一识别符号。
- 高光是偏奶油色的暖白，而不是纯白，形成“内部发光”而非玻璃反光。
- 视线气质集中、平静，适合映射为发送、选中、聚焦和警示等高价值状态。

### 发型与发丝光泽

- 发根和暗部为近黑的深梅紫，主体过渡至灰玫瑰紫，发尾与迎光面出现珠光粉。
- 长发轮廓柔顺连续，但末端存在清晰尖梢，形成“柔软流线 + 局部锐角”的节奏。
- 高光沿发束方向延伸，不采用大面积镜面亮斑；动效应表现为缓慢横向流光。

### 特殊生理与异种特征

- 角色背侧或肩后延展出羽状晶体器官，主色为冰青，内部混有淡紫和蓝色层次。
- 单片晶羽薄、半透明、层叠生长，根部较厚，末端收束为锐利尖端。
- 材质介于晶体、薄羽和发光生物组织之间，边缘亮、内部透，适合转化为切角、边框和冷色光晕。

### 体表与肤色细节

- 肤色为暖象牙粉，阴影带少量玫瑰色，整体柔和且不偏黄。
- 面部识别重点来自眼眸与发色，主题不虚构新的伤痕、纹身或图腾。
- 体表亮部只作为阅读层的暖色调和，不将大面积肤色直接铺成应用背景。

### 体型与骨骼节奏

- 身体轮廓修长、轻盈、柔和，重心稳定，视觉上没有厚重压迫感。
- 发梢和晶羽提供少量尖锐张力，因此组件采用小圆角与单侧切角并存，而不是全圆胶囊形。
- 页面留白和动效节奏偏平静；锐角只用于关键容器、角标与焦点反馈。

## 3. 身体器官级 UI 组件形态转化

### 容器倒角与轮廓

- 普通卡片使用 `8px` 小圆角，映射发丝的柔和曲率。
- 输入框、对话框和关键浮层保留右上 `2px` 锐角，并用渐变边框暗示晶羽切面；承载弹出面板的父容器不得使用 `clip-path`，避免裁断模型选择框。
- 不使用大胶囊卡片，不在卡片内部继续嵌套装饰卡片。
- 分隔线以低透明冰青呈现，模拟晶羽薄边，而不是粗重实线。

### 按钮与高光反馈

- 默认按钮继承深梅紫表面和灰玫瑰边框，保持工作状态安静。
- 发送按钮映射星形瞳孔：中心暖金、外圈橙红、左上奶金高光。
- Hover 时模拟“瞳孔聚焦”：亮部扩大，外光晕增强，按钮仅放大到 `1.06`，不改变布局尺寸。
- Active 时缩放至 `0.97`，使用短促的晶羽弹性曲线。
- 禁用态降低饱和度和光晕，不保留活跃瞳孔反馈。

### 边框与光晕

- 容器默认边框使用低透明冰青，强调半透明晶体边缘。
- 聚焦态切换为暖金瞳芯色，并叠加两层低透明外光晕。
- 阴影以深黑梅紫承担空间层级，晶体冷光仅作为窄范围 Aura，不铺满整个页面。
- 选中项使用发丝玫瑰底色与暖金内侧竖线，兼顾扫描效率和角色识别。

### 绚彩增强层

- 欢迎区叠加粉、金、青三色星尘与同心瞳环，星点保持细小，不使用模糊光斑遮挡正文。
- 像素角色只出现在欢迎空状态，位于标题和输入框之后；角色光晕不得改变交互组件的层级。
- 输入框、新会话按钮和设置弹窗使用发丝粉、晶羽青、星瞳金的流动折射边框，边框动画不改变组件尺寸。
- 侧栏使用低透明星瞳图标水印和纵向晶羽光束，水印不参与点击与键盘焦点。
- 启动页同步使用眼眸背景、图标轨道 Aura、晶羽折射片和粉金青标题渐变。
- 所有装饰伪元素必须 `pointer-events: none`，且不得建立会把弹窗困在主内容层下方的堆叠上下文。

## 4. 专属生理微动效与符号

### Loading：星瞳眨动

- 一个横向眼形容器以 `1.8s` 循环。
- 约在循环的 `47%–50%` 压缩至 `scaleY(0.08)`，形成一次短促眨眼。
- 眨眼前后，星形瞳芯由 `0.78` 放大到 `1.18` 并旋转 `45deg`，模拟视线重新聚焦。
- 同期进度条从深梅紫经过珠光粉流向冰青，表现发丝到晶羽的色彩迁移。

### Switch：闭眼到亮瞳

- 关闭态为深梅紫眼形轨道，滑块是低亮度灰玫瑰虹膜。
- 开启态轨道变为暖梅紫，滑块移动并亮起金色瞳芯，附带小范围暖金光晕。
- 轨道保持固定 `40×23px`，状态切换不能导致布局移动。

### 动效曲线

- 发丝流动：`cubic-bezier(0.22, 0.72, 0.24, 1)`，用于输入框抬升、渐变和持续流光。
- 晶羽弹性：`cubic-bezier(0.2, 0.85, 0.35, 1.22)`，用于按钮按压和 Toggle 滑块。
- 常规过渡控制在 `120–240ms`；持续 Loading 为 `1.35–1.8s`。
- 必须尊重 `prefers-reduced-motion`，将循环与过渡缩短为近乎静态。

## 资产使用约束

- `aemeath-main-background.webp` 用于主会话和欢迎区背景，右侧角色是首要视觉信号；左侧与输入区必须叠加深色遮罩以保证文字可读。
- `aemeath-eye-backdrop.webp` 用于启动和错误状态页面，不能替代主会话背景。
- `aemeath-pixel-assistant.webp` 仅用于空状态或欢迎区，不进入设置弹窗和实际会话正文。
- `aemeath-app-icon.png` 用于应用图标、启动页标记和低透明侧栏水印，缩小到 `32×32` 后仍需能辨认星瞳轮廓。
- 所有图片必须无文字、无水印；角色图优先透明 PNG，并保留发丝与晶羽的细边缘。

## 实现与兼容性

- Electron 主进程在页面加载后注入 `src/aemeath-theme.css`，图片会转成 data URL，发布包不依赖桌面或其他本机目录。
- 动态星空由 CSS 多层径向渐变与 `aemeath-constellation-drift` 驱动，主背景图更换后仍应保留。
- 主题选择器依赖 DeepSeek Harness Web UI 的稳定属性和局部类名；升级 `@deepseek-ai/dsh` 后必须重新检查欢迎页、会话页、模型菜单、设置弹窗和目录选择器。
- 所有持续动画必须遵守 `prefers-reduced-motion`，弹出菜单的祖先容器不得使用会裁切内容的 `clip-path` 或 `overflow: hidden`。
